SCREEN 1 — Homepage
Where is it?

This is literally the main/home screen.

The user opens ShifaKinetix and sees:

"How can we help you today?"

Three options:

Report a Symptom
Book Appointment
Continue Care

That is exactly how the document defines the entry screen.

So your Replit homepage should NOT immediately open a chat.

It should start here.

3. If user clicks "Report a Symptom"

Now we enter the new symptom pathway.

SCREEN 2 — 3D Symptom Intake
HOME
 ↓
Report a Symptom
 ↓
3D Symptom Intake

This is where the patient selects the painful area on the 3D body.

For example:

Right Knee

They can also specify:

superficial/deep
radiation
additional pain point

Then:

Continue

The document explicitly puts the 3D model immediately after Report a Symptom.

4. SCREEN 3 — Red-Flag Questionnaire

After the patient finishes the 3D mapping:

3D Symptom Intake
       ↓
Red-Flag Questionnaire

This is not a homepage feature.

It's part of the Report a Symptom flow.

The questions are based on the selected region, e.g. knee.

5. SCREEN 4A / 4B — Severity Gate

After the questionnaire, there are two possible screens.

If RED FLAG:
Screen 4A
Red-Flag Questionnaire
          ↓
      Severity Gate
          ↓
       RED FLAG
          ↓
   Screen 4A

The patient sees:

We recommend you see a doctor right away.

Then:

Connect to Doctor Now

That's the red-flag branch.

If SAFE:
Screen 4B
Red-Flag Questionnaire
          ↓
      Severity Gate
          ↓
         SAFE
          ↓
      AI Assistant

So Screen 4B is the beginning of the AI chat.

It is not another homepage screen.

AI CHAT

        ┌─────────────┼─────────────┐

The screens in Claude's document are screen designs for these functions, not necessarily separate top-level app pages.

17. SCREEN 15 — X-Ray Upload

Screen 15

19. SCREEN 17 — Appointment Booking

This is one of the screens that does NOT need an existing consultation.

It belongs to the second homepage entry point.

Remember Home:

Book Appointment

So:

HOME
 ↓
BOOK APPOINTMENT
 ↓
SCREEN 17

Patient chooses:

Specialty
Location
Doctor
Date/time
Confirm

This is the direct appointment booking flow.

It does NOT require:

red flags
AI
consultation

The updated architecture explicitly separates direct booking from symptom/AI flows.

20. BUT Screen 17 can ALSO be reached from an existing consultation

There is a second way to reach appointment booking.

For example:

Doctor says:

"You need an in-person assessment."

Then:

Consultation Thread
       ↓
Appointment Escalation
       ↓
Screen 17

So Screen 17 has two entry points:

Entry A
HOME
 ↓
Book Appointment
 ↓
Screen 17
Entry B
Existing Consultation
 ↓
Doctor/System recommends appointment
 ↓
Screen 17

That's why appointment booking shouldn't be thought of as belonging exclusively to the homepage.
